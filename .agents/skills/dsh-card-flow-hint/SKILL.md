# 每张卡一行状态提示：优先级、边界与验证

这类改动看起来只是「加一行字」，实际最容易被两件事做坏：一张卡冒出多行互相矛盾的提示；文案稿写的触发条件在代码里根本不是那个字段。下面按「收敛成纯函数 → 对照代码事实 → 判断改动边界 → 验证与如实记录」走。

## 一、先把提示收敛成一个纯函数

- **一卡一行是硬约束。** 位置固定在元信息行与操作按钮之间，单行 `whiteSpace:nowrap` + 超出省略，不用 `pre-line`。新提示要么进入这个函数争优先级，要么明确替换其中一条，不准另起一行。
- **输出一个选择结果，输入一个显式上下文对象。** 别把判断散在渲染分支里；把状态、档位、开关、各覆盖态布尔、会话 id 与活跃标记都作为入参，函数只返回一个文案键（或无提示）。这样优先级无需浏览器就能测。
- **优先级分三段，先让位、再覆盖、后基础：**
  1. 已有更具体的专属提示（例如孤儿卡说明、上一阶段遗留的评审通知）优先，返回空把这一行让给它，不叠加；
  2. 覆盖态之间互斥，只有一个胜出：人工介入（待补充信息 / 已接管）> 暂停 > 并发排队 > 卡住 > 会话停止；
  3. 最后才按「状态 × 档位」给常态文案（自动 / 手动）。
- 理由：专属提示带着更具体的证据；覆盖态是「此刻最该让用户知道的事实」；基础文案只是常态描述。顺序本身要用「多个条件同时为真时选谁」的用例锁住，而不只是各测一条文案。

## 二、把文案稿的条件逐条翻译成代码事实

文案里的词不等于数据源。编码前逐个读源码确认，校正文案但不改引擎行为：

- **「排队 / 满载」**：代码里常是某个 `action === 'queued'` 或某个 `approvalHeld > 0`，而不是「排队卡片数」这种看着对、实际不存在的量。
- **「会话停止」**：不同阶段看不同会话 id——评审阶段看评审会话 id，构建阶段看构建会话 id；等待人决策的阶段不算会话停止；刚产出新鲜 approved 结论的评审卡也不算。
- **「自动 / 手动」**：未必由档位名直接决定，可能是某档下某个布尔开关为真才自动。按代码里的真实字段拆，不按显示档名猜。
- 每校正一条，就在上下文对象里留下对应入参，并补一条优先级断言。域名术语和触发条件一并记进项目术语表或路线图，避免下次重复争论。

## 三、显示层改动的 `BUILD` 判据

- **不 bump 的条件**：只改客户端渲染与文案字典，且全部输入来自页面已持有的状态快照，接口 / 路由 / schema / 导出面都没变。这是纯显示层：不动 `BUILD`、不动版本号、不碰生成物、不改他人的验收用例。
- **要 bump 的条件**：改了 Host 侧代码、公开导出、路由或状态结构，或需要证明「新代码确实进了运行进程」而不是旧模块继续应答。此时 bump 运行时标记，并按目标仓库约定的方式回读一次状态确认生效。
- 反问句判据：这次改动会不会让「页面看着正常」掩盖「跑的还是旧模块」？不会就不 bump；会就 bump 并真机确认。
- 新文案键遵守目标仓库的占位符清单：不引入新占位符 token，需要在文案里带值时在代码里拼接，而不是改全局占位符约定。

## 四、注入式测试 + 变异验证

- **纯函数层**：直接喂上下文对象覆盖各分支；优先级用「同时为真选谁」的用例钉死顺序；无提示的让位场景也要断言。
- **渲染层**：用注入 / 强制状态跑一次，取节点数、`title === textContent`、computed `whiteSpace`、是否位于按钮之前等结构证据。
- **变异验证**：每拆掉一道判据（去掉某个覆盖优先级、去掉「已有提示压制」、去掉展示用的上下文块），对应断言必须变红；还原后校验文件摘要一致、恢复全绿。红不了说明那条用例只是碰巧绿，形同虚设。
- **字典与基线自足**：多语言一致性用固定清单 + 各副本逐字一致 + 占位符集合固定，不冻结随迭代增长的总数；不拿提交前的 `HEAD` 当期望值。更完整的注入端口与环境无关写法见同仓 `.agents/skills/dsh-plugin-live-verification`。

## 五、真机证据与「未验」的写法

- 真机优先取 DOM 硬证据：文本内容与 `title`、节点数、computed `whiteSpace`、高度、换行数、元素顺序。截图之外这些值可复核。
- 造不出样本的场景（终态、真实并发满、抓不到的会话停止）如实报「未验」并写原因；由代码与单测覆盖即可，不伪造状态、不改环境去凑样本。
- **「离线测试 + 变异通过」不等于真机通过。** 用户选择不补验时，文档仍写「未做真机眼见」，把真机点击验证列为欠项；不要把代码层证据写成真机已验。

## 六、收尾清单

- [ ] 一卡一行、单行 `nowrap`、位于元信息下、按钮之上
- [ ] 优先级集中在同一纯函数；覆盖态互斥不叠加；已有专属提示让位
- [ ] 文案条件逐条对照代码字段，尤其并发、会话停止、档位区分三处
- [ ] 纯显示层未 bump `BUILD`、未动版本号与生成物、未改他人的验收用例
- [ ] 注入用例覆盖优先级顺序；变异拆判据必红、还原摘要一致
- [ ] 真机 DOM 证据与未验项分开如实记录，代码层证据不冒充真机通过
