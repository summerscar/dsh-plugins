# 多来源凭据的优先级与只读状态

插件一旦支持多种登录方式，最容易出的不是「取不到 token」，而是「取到了但说不清是谁、从哪来、下一步该改哪里」。这份 skill 把裁决、状态接口和界面三层的判断固定下来。

## 一、裁决层与展示层分开

- **先做一个单一裁决点**：输入是各来源的记录、本机登录探测、进程环境变量和可选的存活探测，输出只有一个获胜来源。调用方不再自己比较优先级，避免「界面说 A、实际用 B」。
- **内部层级可以比用户可见层多**。例如「另存的全局令牌」和「环境变量里的令牌」在内部是两级（另存的优先），但在界面上都属于「全局令牌」这一层；环境变量只作为该层的默认值出现。层级合并只发生在展示，不改变裁决顺序。
- **展示层只消费裁决结果**：来源 id、是否全局共用、登录名、是否已连接。不要把带 token 的裁决对象直接序列化给 HTTP 或界面；单独提供一个去掉 token 的 view。
- **顺序要能被逐条核对**：从高到低写成一个数组，界面按数组渲染；检查通过时用同一个来源 id 反查「哪一层通过了」。不要在文案里手写另一套顺序。

## 二、环境变量是默认值，不是可写凭据

- 环境变量里的令牌只能读，**永远不要改写进程环境变量**，也不要把它写进插件自己的配置或状态文件。
- 另存的令牌存进凭据服务，属于独立记录；它优先于环境变量使用，但保存/清除只动这条记录。
- 当没有另存记录时，环境变量就是这一层的有效值；当有另存记录时，界面要同时显示两者，并明确「另存优先、环境变量仍是默认值且未被修改」。
- 不要让「保存全局令牌」顺手写回环境变量或配置，否则用户重启后看到的值和界面承诺的不一致。

## 三、只读状态接口：可判断、不可回显

为状态展示提供一个只读接口，返回足以判断「有没有、从哪来、能不能用」的信息，但绝不返回完整 secret。推荐字段：

- `configured`：这一层是否可用。
- `source`：`none` / `env` / `stored`，说明有效值来自哪里。
- `state`：`ok` / `invalid` / `configured` / `none`；`configured` 只表示已配置但没做存活检查，不要冒充 `ok`。
- `login`：令牌对应的账号（探测得到时）。
- `masked`：掩码指纹。
- `env`：独立的环境变量子对象（是否配置、掩码、状态、登录名），即使另存记录优先也要保留，方便用户辨认。
- `overridden`：另存记录是否正在压过环境变量。
- `reason`：失效原因；**不得包含 token 或上游响应里的敏感片段**。

掩码规则要固定并写进用例：

- 长度大于 8：头 4 位 + `…` + 尾 4 位。
- 长度 1–8：整体遮成 `…`，不露任何字符。
- 空值：返回 `null`，不要返回空字符串冒充掩码。

存活探测用一个最小的只读请求（例如读取当前账号）。探测失败时这一层必须判为不可用并继续往下一层落，不能亮假绿；`state=invalid` 要带可读原因。

## 四、界面：修复入口只在失败后出现

- **区分「未配置」和「检查失败」**：未配置时给引导（怎么连、去哪连）；只有一次真正的权限检查返回失败后，才展示修复块。不要把修复入口常驻在页面上，那会让用户以为当前一定有问题。
- **常驻入口行也要随状态隐藏，失败时只留一套入口**：卡片上「全局设置 / 为本仓库补令牌」这类常驻入口行，只在「仓库已绑定、检查结果尚未出（未检查或检查中）」时渲染；权限检查通过、仓库未绑定时一律不渲染。检查失败时，入口只由修复块提供一套（全局设置 + 本仓库令牌），不再保留常驻行，避免同一入口在页面上出现两次。
- **修复块里的作用域要写死**：全局设置就是全局；「仅此仓库」的令牌要写明只作用于当前仓库、不会给其他项目用、只有上面的全局层都不可用时才生效。
- **把非密钥配置放回它所属的块**：OAuth App 的 Client ID 不是密钥，放在 OAuth 连接块内（状态行下、连接按钮上）比单独一张卡更容易理解；一个值全局共用一次即可。创建页要求的回调地址如果产品流程用不到，就明确说「必填但不用、随便填」。
- **环境变量生效时**：点亮它所代表的用户可见层，并标注「来自环境变量（默认值）」；不要新增一个只存在于内部、用户无法配置的层级。
- **保存/清除/重新检查**要各自有明确入口；清除前二次确认，并说明清除后是否会回落到环境变量。

## 五、验收怎么写

- **状态接口**：无配置 / 仅环境变量 / 另存优先 / 失效 / 短令牌全遮 / 空值 / 完整 token 不出现在任何响应里 / `reason` 不含 token。每一条都断言字段值，不只断言 200。
- **优先级**：另存全局 > 环境变量 > 仅此仓库；环境变量存在时仍要能落到仓库令牌；失效的高层要让位给低层，而不是直接失败。
- **文案**：多份字典（内置 zh/en 与打包 locale zh/en）逐字节一致；占位符集合一致；不要写死 key 总数，断言「本轮新增 key 清单 + 四份互等」。
- **不要拿提交状态当基线**：`git show HEAD:` 在测试提交后会变成测试自己，断言必红；用固定常量、本轮新增清单和真实 API 读回。
- **真机**：至少核对层序、当前生效标记、掩码和「失败才出现修复块」。会改真实配置的写操作（保存 Client ID、保存/清除令牌）要单独取得授权，没做就如实记为未验证。
