# dsh-factory

<!-- release-state-note -->

**面向 DeepSeek Harness 的多项目开发工厂：看板上的每张卡都在独立会话与 git worktree 里执行，任何 commit、push 或生成 PR 都必须由你明确批准。**

## 做什么

- **一项目一板。** 按「项目 → 一块看板 → 卡片」组织工作。建项目时会在同一事务里建好它唯一的看板；再为该项目建板只会返回已有的那块。历史多看板数据在加载时收敛：保留第一块活跃板，把其余板上的卡并进去、重指 intake 目标，多余的板标记为归档而不是删除。项目是一个绝对根路径加其下的仓库集合。卡片的仓库信息只作为上下文传给它的会话；卡片实际运行所在的 worktree 始终由项目根路径创建，所以卡片不会改变它在哪个目录里执行。
- **卡片上直接看会话与报告。** 派发过的卡片显示该会话在 DSH 里的实时标题，点一下就跳到那个会话；卡片上的「查看报告」按时间列出这张卡的所有报告（AI 或人工写的），含作者、时间，全文按 Markdown 渲染（原始 HTML 不执行）。弹窗右上角的排序记在浏览器里，默认最新在前；报告编号固定按这张卡的时间正序，不随排序改变。agent 的回复与阶段报告跟随 DSH 里选的显示语言。
- **交付状态与工作中的卡片。** 每张卡都带着 commit / PR 状态，已有 PR 时直接给出可点链接。会话运行中时整张卡会扫过一道蓝光并呼吸发光，不加额外文字横幅。
- **可配置的 worktrees root。** 一个全局设置决定新 worktree 建在哪里；留空即用按用户主目录解析的默认 `~/dsh-factory-worktrees`。它只对之后新建的 worktree 生效，已有项目与卡片不受影响。该根必须位于 DSH 数据目录外，只对默认的主目录子树留一条窄例外。
- **每卡独立会话与 worktree。** 卡片派发时创建专属会话，并在按项目分目录的 git worktree 中隔离执行，两张卡不会共用同一个工作树。
- **阶段接续。** 卡片推进到下一阶段时，插件在同一个 worktree 里接着干，按可用性依次尝试：会话还活着就直接续话；会话已结束但历史在磁盘上就重建到那份历史上；历史不可用才新建会话，并把这次降级记在卡片上。接续永不新建 worktree。
- **连续失败自动停。** 同一张卡连续失败达到 3 次会被标记为已停，不再自动重试，避免反复空转。
- **人工批准的交付。** 插件可以起草提交信息与 PR 描述，但 commit、push 与生成 PR 只在你按下卡片上的专用批准控件后发生。批准计划只在卡片已有报告、且会话已跑完时可用，否则按钮禁用并说明原因。它绝不自行提交、推送、合并或提权。
- **自动拉取 issue。** 从 GitHub 拉取开放的 issue 变成卡片，按仓库与编号去重，重复轮询不会产生重复卡片。
- **内置流程 skill。** 随包提供六个阶段 skill（triage / plan / build / self-review / review / rereview），装好即生效，把每个阶段该做的事交给处理该卡的会话。另有一个添加项目的 skill，教 agent 如何分析一个仓库并注册成项目。
- **建项目时一次性识别 GitHub 绑定。** 建项目时只读本地 git `origin`：只有 github.com 的 HTTPS / SSH 地址会被解析成 `owner/repo`，并在同一事务里和项目默认看板一起写入。没有 remote、非 GitHub、非 git 根目录、或多个 origin 地址都不会阻断建项目，各自记录一个原因码。识别只发生在建项目这一次；引擎运行时不猜仓库、不读 remote。项目设置里可手动改绑或清空。
- **整页式项目管理界面。** 视图按整页设计，有页内吸顶头栏与两种项目导航——侧栏或顶栏标签，用「视图」切换，刷新后仍保持。当前选中的项目也会记住；会话与阶段变化时看板会自己刷新。每项显示项目的自治档位与卡片数。

## 安装

```sh
dsh plugin --profile web add @summerscar/dsh-factory
```

安装后刷新页面，打开左下角**设置**（齿轮），在左侧导航里选「项目工厂」即为看板。

## 使用

1. 建一个项目，填它的绝对根路径。若根目录是 git 仓、且 `origin` 是 github.com 的 HTTPS / SSH 地址，仓库会自动填好；否则项目照常创建，原因会显示在设置里。页头显示当前绑定状态，点它打开该项目的绑定输入框。
2. 在项目自带的看板上建卡片；或用 intake 从 GitHub 拉取 issue。
3. 把卡片派发出去，它会在自己的会话与 worktree 里执行。
4. 卡片停在「待批准计划」时，点一次「批准计划」即完成两件事：转移到 `build` 并接着原会话/原 worktree 继续跑，agent 随即开始实现，无需再点第二次。
5. 之后卡片推进到下一阶段时走接续：同一个 worktree、同一条分支，只重新拿到会话（会话还活着就直接续，结束过就接回历史，历史没了才新建并记下降级）。卡片上显示已关联会话的标题，点它跳到那个会话；「查看报告」打开这张卡所有阶段的报告。
6. 在评审阶段查看改动，按「确认提交」再按「推送分支并创建 PR」——这两步都是你的动作，插件不会代劳。开出的 PR **一律是 draft**（所有自治档位——`manual` / `you-approve` / `machine-approve`，新项目默认 `manual`），合并永远留给人。
7. draft PR 开出后卡片停在评审，由你决定标记完成还是打回。
8. 从某个项目打开设置会直接落在**该项目**的设置页；「全局设置」页签（或项目页上的「全局设置 ›」入口）里是 worktrees 根目录、GitHub 连接、全局并发与引擎开关。没有项目时，抽屉打开即全局设置。
9. 用「视图」在侧栏与顶栏标签之间切换，刷新后仍保持。项目卡上的 GitHub 按钮只跳到全局连接设置——连接只在全局页做，不在项目里发起。切自治档位时只有切进 `machine-approve` 会先二次确认、切离不弹——该档不看任何开关，档位即唯一真相源。保存后有短暂的 toast 提示。

## 命令

在会话里用 `/factory` 注册项目：

- `/factory add` — 把当前会话的工作目录注册为项目。
- `/factory add <绝对路径> [项目名]` — 注册指定仓库；不给项目名时用目录名。
- `/factory inspect <绝对路径>` — 只读列出仓库的原始特征：根目录的文件名与子目录名、各 ignore 文件的条目、值得一读的清单文件、`package.json` 声明的包管理器。它不判定项目类型，也不创建任何东西。

`add` 不会自己建项目：它把请求交给当前会话的 agent，由 agent 按内置的 `factory-add-project` skill 先调 `factory_inspect_repo` 拿到仓库的原始特征，再自己读关键文件判断真实技术栈、提议 `copyFiles` 与 `postCreate`，经你确认后建项。安装命令与需要复制的本地文件由**目标仓库自己的** `AGENTS.md` / `CONTRIBUTING` 决定，插件不预设。

## GitHub 接入

每个项目自己判断用哪个 GitHub 身份，项目里的**身份卡**用大白话把结果摆出来：当前用的是哪个账号（需要时从本机 `gh` 登录只读解析）、来源是哪一档、本地目录是否绑到了正确的远端仓库、以及一项可以随点随查的权限检查。卡片按优先级列出四层身份并高亮当前生效层；检查通过时会写明是哪一层通过的。若来源已连接但读不到账号名，卡片显示来源，而不是「无法识别账号」一类占位说法。全局来源连一次，所有项目都能用。

仓库绑定（`owner/repo`）与身份是两回事：建项目时从 github.com `origin` 识别一次，可在项目设置里手动改绑或清空（留空即解绑）。连接与 OAuth 只在全局设置里；项目卡上的 GitHub 按钮只带你去那里。

来源分三种，作用域由种类定死（个人访问令牌按作用域分成全局与仅此仓库两层，所以身份卡显示四层）：

- **一个 GitHub OAuth App**——通过设备码流程连一次，连接对所有项目共用（这一档没有按项目开的开关）。用它要自己[创建 OAuth App](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app)并勾选设备码流程，把它的 Client ID（不是密钥，一个值所有项目共用）填进插件，再到 [github.com/login/device](https://github.com/login/device) 输入 GitHub 给的八位码。创建页面还会要求填 Homepage URL 和 Authorization callback URL；设备码流程不用回调地址，随便填个网址即可。
- **你机器上的 `gh` 登录**——已经跑过 `gh auth login` 就直接用，不额外存任何东西。账号管理区会显示 `gh` 是否已登录成某个账号，没登录时告诉你怎么登。
- **一个个人访问令牌**——只有这一档由你选作用域：**所有项目共用**，或**只给一个仓库**。

插件按「谁能真正够到这个仓库」取第一档命中：先是共享的 OAuth App，再是 `gh` 登录，再是全局 GitHub Token，最后是**只给这个仓库**的 Token（兜底层）。`GH_TOKEN` / `GITHUB_TOKEN` 环境变量是全局 Token 这一层的**默认值**；可以在页面里另存一个自己的全局 Token，使用时优先于环境变量，环境变量本身不会被改动。已连接某个身份、但权限检查不通过时，卡片下面才给出两处可改的配置：全局 GitHub 设置，以及**仅适用于当前仓库**的 Token。卡片底部常驻的入口行（全局设置；为本仓库填写 Token）只在仓库已绑定且尚未出检查结果（未检查、或检查中）时显示；检查通过、未绑定仓库时都不显示，检查失败时页面上只剩修复块这一套入口，不再重复。

手动保存的令牌存进 DSH 凭据，不写进配置、日志或状态文件。插件不内置任何 OAuth 凭据。全局设置按优先级列出三层：① 共享 OAuth App——**连接**、**重设**（用新连接替换旧的）或**断开**；② `gh` CLI 登录状态；③ **全局 GitHub Token**——保存、清除或重新检查。Client ID 输入框在 ① 块内，位于状态行下、连接按钮上，一个值所有项目共用。配置了环境变量时，设置页会显示「已配置 gh token 环境变量」以及掩码（只露头尾各四位；八位及以下的值整体遮成「…」），方便辨认是哪个 Token；另存的全局 Token 会明确标为优先使用者。完整值绝不回显。

另有一个只读接口 `GET /api/dsh-factory/auth/token/state` 支撑这块状态显示：它报告全局 Token 是否已配置、来源是环境变量还是另存的 Token、是否有效、对应的登录名，以及一个掩码指纹；任何情况下都不返回完整 Token。

参考：[授权流程](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps) · [创建入口](https://github.com/settings/applications/new) · [设备码输入](https://github.com/login/device)

## 主要限制

- **绝不自动执行 git 操作。** 没有人在卡片上按下批准控件，插件就不会 commit、push、开 PR 或合并。
- **暂停不会停掉已在跑的会话。** 全局与项目级的暂停/恢复、卡片级接管现在在设置界面都有入口；暂停只挡之后的 tick，所以已在跑的会话会接着跑。接口仍是 `POST /api/dsh-factory/engine/pause` / `.../resume` 与 `POST /api/dsh-factory/cards/<卡片 id>/takeover`（是 `takeover`，不是 `take-over`）。
- **远端状态只生成建议、不自动应用。** `POST /api/dsh-factory/cards/<卡片 id>/remote-sync` 接收远端 PR 快照，只记录一条待人处理的建议——绝不改变卡片所在列，也不会替你批准计划。
- **没有 webhook。** 走 `gh` 与轮询，所以 issue 变化不是实时的，取决于轮询间隔。
- **只支持 GitHub。** GitLab 的评审流程尚未实现。
- **单机。** 面向在本机运行的 DSH，不提供多副本协调。
- **OAuth 连接是活的设备码流程。** 它在你的浏览器里跑、只在当前这个页面会话内保持：跑的过程中刷新页面会取消它，码没在流程的时间窗内填完就得重新发起连接。
- **重设只是本地断开。** 插件会清掉已存的连接、并给你一个去 GitHub 设置页撤销的链接，但它无法替你在 GitHub 上撤销令牌（它没有你那个 OAuth App 的 client secret）；远端撤销是你在 GitHub 网页上的动作。
- **只给某个仓库存的令牌只帮那个仓库。** 存来共用的令牌对所有项目生效，存给单个仓库的只在那儿生效。
