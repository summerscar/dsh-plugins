## 做什么

dsh-factory 把仓库变成一条自运转的开发流水线：你在看板上管理项目，引擎把每张卡从 issue 带到评审过的分支，合并按钮始终在你手里。

- **一项目一工厂。** 工作按「项目 → 一块看板 → 卡片」组织。项目是一个绝对根路径加其下的仓库集合，看板随项目一起创建。整页式管理界面提供侧栏与顶栏标签两种导航（用「视图」切换），刷新后仍记住视图与选中项目，会话与阶段变化时看板自己刷新。
- **天然隔离。** 每张派发出的卡片都有专属 DSH 会话，并在按项目分目录的 git worktree 中执行，两张卡永不共用工作树。全局的 worktrees 根目录决定新 worktree 建在哪；留空即用 `~/dsh-factory-worktrees`。该根必须位于 DSH 数据目录之外。
- **两段独立评审的自动流水线。** 收件箱 → 分类 → 规划 → 构建 → 自审 → PR 评审 → 完成。构建会话验证改动、只提交决策时冻结的路径并推送卡片分支——不开 PR。独立的自审会话检查已推送分支，批准时从后端重读的准确 head 开出唯一 **draft** PR。第三个只读的 PR 评审会话在 PR 上写结论。合并由你完成；只有真实的远端合并事实出现，卡片才进入 `done`。任何路径都不合并、关 issue、强推或写别的分支。
- **接续而非重来。** 推进阶段时沿用同一个 worktree 与分支：会话还活着就续话，已结束就接回磁盘上的历史，只有历史不可用才新建会话，并把降级记在卡片上。连续失败 3 次的卡片会被标记为已停，不再自动重试。
- **issue 自动进件、按仓库与编号去重。** 绑定 GitHub 仓库与目标看板后，每轮轮询把开放 issue 变成卡片，按仓库与编号去重。绑定是显式的——引擎运行时不猜仓库——可在项目设置里改绑或清空。
- **阶段规则只能收窄。** 默认全速自动。六行阶段规则里只有四条有引擎读点、可关掉让卡片停等人：收件箱-自动启动、规划-自动批准、自审-自动启动、PR 评审-自动启动。其余勾选固定开启、置灰并带悬浮说明。暂停项目或接管卡片也会挡住后续自动步骤。
- **内置流程 skill。** 安装即注册分类、规划、构建、自审、评审、重评六个阶段 skill，以及一个用 `/factory` 分析仓库并注册成项目的 skill。安装命令与要复制的本地文件来自**目标仓库自己的** `AGENTS.md` / `CONTRIBUTING`，插件不预设。
- **卡片上直接看会话与报告。** 派发过的卡片显示实时会话标题，点一下就跳到那个会话；「查看报告」列出所有阶段报告（作者、时间，全文按 Markdown 渲染，原始 HTML 不执行）。回复跟随 DSH 里选的显示语言。

## 安装

```sh
dsh plugin --profile web add @summerscar/dsh-factory
```

安装后刷新页面，打开左下角**设置**（齿轮），在左侧导航选「项目工厂」即为看板。

## 使用

1. 建一个项目，填绝对根路径。若根目录是 git 仓、`origin` 是 github.com 的 HTTPS / SSH 地址，仓库绑定会自动填好；否则项目照常创建，原因显示在设置里。页头显示当前绑定，点它可改。
2. 在项目自带的看板上建卡片；或用 intake 从已绑定的仓库拉取 issue。
3. 派发卡片，它会在自己的会话与 worktree 里执行；卡片上能看到关联的会话与所有阶段报告。
4. 计划默认自动批准，卡片从 `plan` 转到 `build`、在原 worktree 里继续。想让某阶段停等人，就在项目设置里关掉对应规则；暂停项目或接管卡片同样会挡住后续自动步骤。
5. 构建会话推送卡片分支、不开 PR；独立自审会话检查后从批准 head 开出唯一 **draft** PR；另有只读的 PR 评审会话写结论。由你合并那份 draft PR。宿主观察到已合并时，`syncRule` 把卡片移到 `done`；未合并就关闭只会生成退回 `build` 的建议。

### 在会话里注册项目

- `/factory add` — 把当前会话的工作目录注册为项目。
- `/factory add <绝对路径> [项目名]` — 注册指定仓库；不给项目名时用目录名。
- `/factory inspect <绝对路径>` — 只读列出仓库原始特征（根目录条目、ignore 文件、清单文件、声明的包管理器），不判定项目类型，也不创建任何东西。

`add` 把请求交给会话里的 agent，按内置的添加项目 skill 先分析仓库、再读关键文件、提议 `copyFiles` 与 `postCreate`，经你确认后建项。安装命令与要复制的本地文件来自目标仓库自己的 `AGENTS.md` / `CONTRIBUTING`。

### GitHub 接入

每个项目自己判断用哪个 GitHub 身份，并在**身份卡**上写明：当前账号、来源、本地目录是否绑到正确远端，以及可随点随查的权限检查。四层身份按优先级列出并高亮生效层；连上了但读不到账号名时，显示来源而不是占位说法。

优先级从高到低：共享的 **OAuth App**（设备码流程，在全局设置连一次，所有项目共用）、机器上的 **`gh` 登录**（直接用，不存任何东西）、**全局 Token**（所有项目共用）、**仅此仓库的 Token**（兜底）。`GH_TOKEN` / `GITHUB_TOKEN` 是全局 Token 这一层的默认值；另存的全局 Token 优先，环境变量本身不会被改动。令牌存在 DSH 凭据里，不进配置、日志或状态文件；插件不内置任何 OAuth 凭据。身份卡只显示掩码指纹，不回显完整值。

连接与 OAuth 只在全局设置里；项目卡上的 GitHub 按钮只带你去那里。仓库绑定（`owner/repo`）与身份是两回事：建项目时从 github.com `origin` 识别一次，可在项目设置里改绑或清空。

## 主要限制

- **git 边界固定。** 构建会话提交并推送自己的分支；自审评审人从批准 head 开出唯一 draft PR。任何路径都不合并、关 issue、强推或写别的分支。可切换的阶段规则只能让阶段停下，不能放宽这个边界。
- **暂停不会停掉已在跑的工作。** 全局与项目级的暂停/恢复、卡片级接管会挡住引擎的自动步骤（派发、批准计划、自审、交付），但已在跑的会话继续，恢复后不补跑跳过的卡。issue 进件跟随仓库绑定，每轮都拉，暂停也不停。
- **手动远端同步只生成建议。** 记录远端 PR 快照不会改变卡片列、也不替你批准计划；`done` 只来自引擎轮询到的真实合并事实。
- **没有 webhook。** issue 变化按轮询间隔到达，不是实时的。
- **只支持 GitHub。** GitLab 评审流程尚未实现。
- **单机。** 面向本机运行的 DSH，不提供多副本协调。
- **OAuth 是活的设备码流程。** 它在浏览器里跑、只在当前页面会话内保持：跑到一半刷新页面会取消，码没在时限内填完就得重来。重设只是本地断开，插件无法替你在 GitHub 上撤销令牌。
- **仅此仓库的令牌只帮那个仓库。** 存来共用的令牌对所有项目生效。
